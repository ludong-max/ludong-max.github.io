WorldExplorer: Towards Generating Fully Navigable 3D Scenes

arXiv PDF Project Page GitHub
One-sentence problem: Existing 3D scene generation methods break down under large camera movements — can we build scenes that remain stable and visually consistent when the user truly navigates freely, including going around objects and large translations?
一句话问题：现有 3D 场景生成方法在大幅摄像机运动下会崩溃 — 能否构建在用户真正自由导航（包括绕物体运动和大范围平移）时仍保持稳定和视觉一致的场景？
与 WonderWorld 系列的核心差异：
WonderWorld 系列：单图 → 深度扩散 inpainting → 分层 Gaussian surfels（每步逐渐外推）
WorldExplorer：文本 → 360° 全景初始化 → 视频扩散多轨迹探索 → 场景记忆条件 → 3DGS 融合
前者快、交互性强；WorldExplorer 更注重大视角范围内的一致性，适合完整场景浏览。

Key Contributions

  • 360° panorama initialization: Instead of starting from a single perspective view, WorldExplorer first generates a multi-view-consistent 360° panoramic scaffold of the scene, providing a complete coverage anchor before detail is added.
    360° 全景初始化：与从单视角出发不同，WorldExplorer 首先生成多视角一致的 360° 全景场景支架，在添加细节前提供完整的覆盖锚点。
  • Autoregressive video trajectory generation: Scene content is expanded iteratively along short pre-defined camera trajectories using a video diffusion model, generating multiple short video clips that progressively explore the scene in depth — including motions around objects.
    自回归视频轨迹生成：场景内容沿预定义的短摄像机轨迹通过视频扩散模型迭代扩展，生成多个短视频片段，逐步深入探索场景（含绕物体运动）。
  • Scene memory mechanism: Each new video clip is conditioned not only on the current view but also on the most relevant prior views retrieved from a scene memory store. This prevents the model from "forgetting" previously generated content and maintains long-range consistency.
    场景记忆机制：每个新视频片段不仅以当前视图为条件，还以从场景记忆库检索的最相关历史视图为条件，防止模型"遗忘"已生成内容，维持长程一致性。
  • Collision-detection for trajectory planning: A collision-detection mechanism prevents the camera trajectory planner from moving into already-generated geometry, avoiding degenerate cases (e.g., camera flying through walls or floors).
    碰撞检测轨迹规划：碰撞检测机制防止摄像机轨迹规划器穿入已生成几何体，避免退化情况（如摄像机穿墙或穿地板）。
  • 3DGS fusion from multi-video views: All generated video frames across trajectories are fused into a unified 3D Gaussian Splatting representation via optimization, producing a single navigable 3D asset from the entire set of generated views.
    多视频视图融合为 3DGS：所有轨迹生成的视频帧通过优化融合为统一的 3D Gaussian Splatting 表示，从全部生成视图产生单一可导航的 3D 资产。

Method / Architecture

Text prompt → 360° panorama generation (multi-view consistent) → Trajectory planner + collision detection → Video diffusion: short clip along trajectory → Scene memory: condition on relevant prior views → repeat for next trajectory … → 3DGS optimization (all frames fused) → Fully navigable 3D scene

Panorama initialization: A 360° image is generated from the text prompt using a panoramic diffusion model (or text-to-panorama pipeline). This provides a coarse but globally consistent scene layout covering all directions before any trajectory is explored.

Video diffusion per trajectory: For each pre-defined short camera trajectory (e.g., a forward push, a lateral sweep, or an orbit around an object), a video diffusion model generates a temporally consistent clip. The model is conditioned on the rendered partial scene plus the scene memory retrieval.

Scene memory: A key-value store of previously generated views, indexed by camera pose. When generating a new clip, the most similar prior views (by pose distance) are retrieved and injected as context into the video diffusion model, acting as long-range visual anchors.

3DGS fusion: After all trajectories are generated, all frame sets are combined and a 3D Gaussian Splatting optimization (similar to standard 3DGS training) is run over all views simultaneously. This produces a single unified 3D representation that can be rendered from arbitrary novel viewpoints.

全景初始化：用全景扩散模型（或 text-to-panorama 管线）从文字提示生成 360° 图像，在探索任何轨迹前提供粗略但全局一致的场景布局。

逐轨迹视频扩散：对每条预定义短摄像机轨迹（前推、侧扫或绕物体轨道），视频扩散模型生成时序一致的视频片段，以已渲染部分场景和场景记忆检索结果为条件。

场景记忆：以摄像机位姿为索引的历史视图键值存储；生成新片段时检索最相似的历史视图（按位姿距离），注入视频扩散模型作为长程视觉锚点。

3DGS 融合：所有轨迹生成完毕后，对全部帧集合同时运行 3D Gaussian Splatting 优化（类似标准 3DGS 训练），产生单一统一的 3D 表示，可从任意新视角渲染。

Limitations

  • No single-image input: WorldExplorer starts from a text prompt and panorama, not an existing photo. Adapting it to extend a user-provided photograph requires additional conditioning not present in the current design.
    不支持单图输入：WorldExplorer 从文字提示和全景图出发，而非已有照片。适配用户提供的照片需要额外的条件机制。
  • Slow — not interactive: Multi-trajectory video generation + 3DGS optimization takes minutes, making real-time user steering impossible. It is a batch process, not an interactive tool like WonderWorld.
    慢 — 非交互：多轨迹视频生成 + 3DGS 优化耗时数分钟，不支持实时用户引导，是批处理流程而非 WonderWorld 那样的交互工具。
  • Text-driven only — limited precise control: Scene content is determined by text prompts. Fine-grained object placement, layout control, or user-specified structures require prompt engineering with no direct spatial manipulation.
    仅文字驱动 — 精确控制有限：场景内容由文字提示决定，精细物体放置、布局控制或用户指定结构需要提示工程，无法直接空间操作。
  • Memory retrieval quality bottleneck: The scene memory relies on pose-based retrieval; in scenes with repeated structures (hallways, forests), retrieval errors can cause inconsistent conditioning and visible artifacts.
    记忆检索质量瓶颈：场景记忆依赖位姿检索；在有重复结构的场景（走廊、森林）中，检索错误可能导致不一致的条件和可见 artifact。

TL;DR

WorldExplorer (TU Munich, SIGGRAPH Asia 2025, arXiv 2506.01799) takes a fundamentally different route from the WonderWorld family: it generates fully navigable 3D scenes from text prompts via 360° panorama initialization → autoregressive video diffusion along multiple trajectories → scene memory conditioning → unified 3DGS fusion. Its key advantage is stability under large camera motion and 360° scene coverage; its key disadvantage is batch-processing latency (minutes, not seconds) and no single-image input support. For related-work sections, cite WorldExplorer when discussing scene completeness and large-viewpoint consistency, and WonderWorld/Turbo for interactive single-image generation.
