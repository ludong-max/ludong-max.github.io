One-sentence problem: Starting from any location (text or image), can we generate an open-ended, coherent journey through a long sequence of diverse and connected 3D scenes?
一句话问题：从任意起点（文字或图像），能否生成一段开放式、连贯且多样的长序列 3D 场景旅程？
团队演进线：WonderJourney (CVPR 2024) → WonderWorld (CVPR 2025) → WonderPlay (ICCV 2025)

Key Contributions

  • Modular perpetual scene generation framework: WonderJourney separates scene description (LLM), 3D generation (point cloud pipeline), and quality verification (VLM) into independent modules, making each component replaceable as stronger models emerge.
    模块化永续场景生成框架：将场景描述（LLM）、3D 生成（点云管线）和质量验证（VLM）解耦为独立模块，随着模型迭代可单独替换各组件。
  • LLM-driven narrative coherence: An LLM generates textual descriptions for each scene step, ensuring semantic continuity across the journey (e.g., walking from a forest to a lakeside village) without requiring per-scene manual prompting.
    LLM 驱动叙事连贯性：LLM 为每步场景生成文字描述，确保跨场景的语义连续性（如从森林走到湖畔村庄），无需手动逐场景提示。
  • Text-driven point cloud generation pipeline: Each scene step is realized as a point cloud generated from depth estimation + inpainting, conditioned on both the text description and the previous scene geometry to maintain spatial consistency.
    文本驱动点云生成管线：每步场景由深度估计 + inpainting 生成点云，同时以文本描述和前一场景几何为条件，保持空间一致性。
  • VLM-based scene verification: A vision-language model evaluates whether each generated scene matches its text description and is visually plausible, triggering regeneration when quality falls below threshold.
    VLM 场景验证：视觉语言模型评估每个生成场景是否与文字描述匹配且视觉合理，低于阈值时触发重新生成。
  • Open-domain starting point: Unlike prior work that assumes a fixed scene type (indoor, outdoor), WonderJourney accepts arbitrary start locations described by text or a single image, making it domain-agnostic.
    开放域起点：与仅限室内或室外的先前工作不同，WonderJourney 接受文字或单张图像描述的任意起点，实现跨域场景生成。

Method / Architecture

Text / Image input → LLM: scene sequence description → Step i: RGB inpainting + depth estimation → Point cloud layer i → VLM verification → repeat for step i+1 …

LLM planning: Given the starting location, an LLM generates a narrative sequence of scene descriptions for the entire journey. Each description specifies the next scene's content and its relationship to the previous one (e.g., "cross the wooden bridge, entering a misty bamboo grove").

Point cloud generation per step: A monocular depth model converts the current view (inpainted RGBA + depth) into a point cloud. Newly exposed regions are filled by an RGB inpainting diffusion model conditioned on the LLM scene description, then lifted back into 3D via a depth completion model.

VLM verification: After generating each scene step, a VLM (e.g., GPT-4V or similar) compares the rendered view against the LLM description. If the match score is too low, the step is re-sampled with a modified prompt.

Key limitation vs WonderWorld: Point cloud representation leads to aliasing and holes at boundaries; generation per step takes >700 seconds — the main motivation for WonderWorld's FLAGS + guided depth diffusion redesign.

LLM 规划：给定起点，LLM 为整个旅程生成场景描述序列，每步描述下一场景的内容及其与前一场景的关系（如"穿过木桥，进入薄雾竹林"）。

逐步点云生成：单目深度模型将当前视图（inpaint RGBA + 深度）转为点云；新暴露区域由以 LLM 描述为条件的 RGB inpainting 扩散模型填充，再通过深度补全模型提升回 3D。

VLM 验证：生成每步场景后，VLM 将渲染视图与 LLM 描述对比，匹配分低于阈值则以修改后的提示重新采样。

相比 WonderWorld 的核心局限：点云表示在边界处易出现走样和空洞；每步生成耗时 >700 秒 — 这正是 WonderWorld 重新设计 FLAGS + 引导深度扩散的主要动机。

Limitations

  • Very slow generation: Each scene step requires >700 seconds, making real-time or interactive use impossible — the primary bottleneck addressed by WonderWorld.
    生成极慢：每步场景需 >700 秒，无法实时或交互使用 — WonderWorld 着力解决的核心瓶颈。
  • Point cloud artifacts: Boundaries between scene steps exhibit aliasing, holes, and floating points that degrade rendering quality under novel viewpoints.
    点云 artifact：场景步骤间边界出现走样、空洞和悬浮点，在新视角下渲染质量下降。
  • LLM hallucination risk: Textual coherence from the LLM does not guarantee visual coherence — inconsistent lighting, style breaks, or semantically plausible but visually jarring transitions can occur.
    LLM 幻化风险：LLM 的文字连贯不保证视觉连贯，可能出现光照不一致、风格断裂或语义合理但视觉突兀的场景过渡。
  • No user interactivity: The journey is fully scripted by the LLM. Users cannot steer in real time, add objects, or modify the generated scene after creation.
    无用户交互：旅程由 LLM 全程脚本控制，用户无法实时引导、添加物体或在生成后修改场景。

TL;DR

WonderJourney (Stanford + Google, CVPR 2024, arXiv 2312.03884) is the predecessor of WonderWorld by the same team. It generates open-ended perpetual 3D scene journeys from any text or image starting point using an LLM for narrative planning, a point cloud pipeline for 3D generation, and a VLM for quality verification. Its critical limitation — >700s per scene step — directly motivated the WonderWorld redesign with FLAGS and guided depth diffusion. Reading WonderJourney first clarifies why WonderWorld made its key architectural choices.
